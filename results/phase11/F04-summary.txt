CRITICAL OBSERVATION — Direction of the qdisc:

The tbf was applied to ogstun2 egress. On a TUN interface, egress is
the direction from the host network stack INTO the UPF. This is the
DOWNLINK direction (edge-app -> UE). iperf3 ran in the uplink direction
(UE -> edge-app), which traverses ogstun2 ingress and is NOT limited by
this qdisc.

As a result, iperf3 still hit the UE uplink ceiling (~7 Mbps), not the
configured 2 Mbps tbf cap. The test was not able to demonstrate an
uplink throughput throttle on the edge path.

This is not a bug. It is a real directional finding:

- The rate limit applied to the downlink of one UPF.
- Uplink throughput through the same UPF is not affected by an egress
  qdisc.
- Downlink HTTP response traffic IS affected when the link is congested,
  which is why the HTTP probe's p95 grew by ~660 ms under competition
  from the concurrent iperf3 test.

WHY THE LATENCY INCREASED:

The tbf was configured with a 32 KB burst. When both the HTTP probe's
response and iperf3's TCP ACK traffic (which travels downlink) competed
for the 2 Mbps token bucket, the burst occasionally depleted, queuing
small HTTP responses behind larger ACK bursts. This is visible as
increased p95 latency but not as a throughput cap on the HTTP path
(HTTP traffic is too small to trigger sustained throttling).

RECOVERY:
- ogstun2 qdisc restored to fq_codel (default)
- The recovery-window p50 (124 ms) is essentially the same as baseline
  (159 ms), confirming no residual effect.

CROSS-PATH ISOLATION:
- Zero errors on either probe throughout the test.
- The central path was not affected (in fact its p50 improved during the
  fault window, most likely due to DU scheduler warm-up).
- This confirms Phase 7's multi-UPF isolation: a bandwidth limit on one
  UPF's TUN interface does not propagate to the other UPF's path.

LIMITATION OF THIS TEST:
A stricter bandwidth-throttle test should either:
(a) place the qdisc on the correct directional interface (for example,
    an ingress qdisc on ogstun2, or an egress qdisc on the UE namespace's
    veth or tun), or
(b) run iperf3 in the direction that traverses the qdisc (i.e. iperf3 -R
    for reverse mode, testing downlink throughput).
Both are straightforward follow-ups, but were not run here.

CONCLUSION:
F04 demonstrates partial but valid findings:
1. Bandwidth limiting on one UPF's TUN interface does not affect the
   other UPF (cross-path isolation is preserved).
2. HTTP latency on the limited path increases under competition
   (downlink response traffic shares the constrained bucket).
3. iperf3 in the wrong direction does not experience the tbf cap; this
   is a methodological limitation and is documented here for honesty.
4. The tbf was correctly and cleanly removed after the test.
