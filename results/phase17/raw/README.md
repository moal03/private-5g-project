# Phase 17 — Raw result files

## What is here

Small per-study CSVs with one row per simulation run:

- `s1_ngmn.csv`     — S1 scalability (25 runs)
- `s2_qos.csv`      — S2 QoS (12 runs)
- `s2_flows.csv`    — S2 per-flow summary (36 flows)
- `s3_beamforming.csv` — S3 beamforming (18 runs)
- `s4_fronthaul.csv` — S4 fronthaul (9 runs)
- `s5_simple_qos.csv` — S5 simple QoS (6 runs)
- `s6_ca.csv`       — S6 carrier aggregation (6 runs)
- `s7_mimo.csv`     — S7 MIMO (6 runs)
- `s8_notching.csv` — S8 notching (9 runs)
- `s9_xr.csv`       — S9 XR traffic (9 runs)
- `s10_numerology.csv` — S10 numerology (12 runs)
- `s11_bandwidth.csv` — S11 bandwidth (12 runs)
- `s12_frequency.csv` — S12 frequency (9 runs)
- `s13_tdd.csv`     — S13 TDD pattern (15 runs)

## What is NOT here

Two very large CSVs from study S2 are not committed, because they are
regenerable from raw ns-3 trace files and would bloat the repository:

- `s2_packets.csv` (~2.7 MB, 67,871 packet-level rows)
- `s2_qos_per_flow.csv` (~3.5 MB, per-flow delay samples)

They can be regenerated by running:

    python3 ../../scripts/phase17/parse_all_studies.py

on a machine with the raw ns-3 output files for study S2.
